# Duo Fold Live 3.5.5-alpha.9

Incoming-screen ghosting diagnosis, not a claimed fix.

Developer settings now include Incoming ghosting diagnostic with Normal animation (default), Raw capture, and Solid magenta. Selection affects only the incoming screenshot-mode panel and resets on app process restart. Outgoing screenshots, normal Live Screen mode, task routing and endpoint power behavior are preserved.

Both tests use the same actual incoming SurfaceView as the animation. Raw capture displays the accepted frame full-screen over an opaque backdrop, without the glass shader. Solid magenta paints the entire cover or the animated inner half including its seam, bypassing captured pixels and the shader. Both require a valid incoming frame/session; do not interpret absence of the test pattern as a result.

The screenshot report retains the most recent diagnostic draw's selected test, physical panel, display, frame timestamp/age, dimensions, rotation and the actual capture-exclusion surfaces submitted for that frame. These are software observations, not proof of visible pixels or effective exclusion.

## Test

1. Select Screenshot Mode and Developer settings → Incoming ghosting diagnostic → Raw capture. Fold and unfold slowly in a fullscreen app. Is the incoming image clean or already doubled?
2. Repeat with Solid magenta. Does any app text remain visible inside the magenta region? On the inner screen, the other half intentionally remains normal.
3. Copy the screenshot-mode test report after each test and note the visual result. A short video is useful.
4. Restore Normal animation afterward.

If magenta also shows text, investigate compositing/layer order. If magenta is solid but raw capture is doubled, investigate capture contamination. If both tests are clean but animation doubles text, investigate the shader/animation blending. Endpoint blanking remains deferred.
