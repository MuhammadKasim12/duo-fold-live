# 3.5.3-alpha.24

Screenshot is now a main animation-style choice. Selecting it applies the screenshot window-first route, closing app-first return and closed-hinge jitter protection, with Samsung ON overrides off. The advanced switches remain in Developer settings. Other styles retain their normal routing.

The Screenshot preset enables Screenshot endpoint black fade and disables the incoming app screenshot hold. It prepares independent hosts, masks the incoming physical screen near the endpoint (15 degrees closing; 8 degrees before the configured open endpoint), holds black through remapping, and fades into the exact app after two readiness observations and the existing settle interval. Reveal duration follows the existing fade gradualness setting (292 ms at default). Lock, stale-angle, reversal and bounded timeout cleanup remain in effect. The black path does not capture an incoming screenshot. Outgoing screenshot diagnostic labels are omitted in the main Screenshot style.

A temporary loss of fixed-panel readiness now receives a continuous 2.5-second recovery window rather than immediately failing any session already older than 2.5 seconds. Physical-primary identity and overall session time limits remain unchanged.

Tests cover both endpoint fade thresholds, invalid angles and Screenshot mode selection, alongside existing lease and routing tests. On-device testing is still required; this masks the transition rather than eliminating the physical display OFF interval.
