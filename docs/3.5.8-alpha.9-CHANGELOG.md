# 3.5.8-alpha.9 — compositor blur with screen stretch experiment

Normal glass remains the default with its existing shader, blur, stretch curves,
settings and handoff timing unchanged. The alpha.8 system blur-only option remains
available unchanged for visual comparison.

New Live Screen developer option: **System compositor blur + stretch (experimental)**.
It renders the existing projection with shader blur disabled, then places an owned
SurfaceControl effect child above that buffer to blur the projected image. Existing
startup/end stretch, compression, easing and motion settings still drive projection.
The child is cropped to the buffer, inherits the renderer transform/visibility, and
is excluded with its parent from captures. Updates are submitted with the buffer;
clear/fallback frames hide blur. Standby, mode exit and destruction remove the child.
Unsupported API calls fall back to projection without blur and report the failure.
Android can suppress blur despite accepting a transaction.

This is an experiment: a compositor blur over projected content may differ from
blur-only in appearance, clean regions and clipping. It needs physical-device checks
on both displays, reversals, endpoints and rotation. It does not claim optical
continuity or fix capture/reveal latency. Existing readiness gates remain in place.

Diagnostics label new draws/commit callbacks SYSTEM_PROJECTED_DRAW/COMMIT and include
the rendering mode in first-frame notes. These are software events, not pixel timing.

Suggested comparison: Normal → System blur-only → System blur + stretch, using the
same content and stretch settings. Confirm stretch and blur together, no feedback,
no lingering blur after opening/closing or changing mode, then compare handoff feel.
