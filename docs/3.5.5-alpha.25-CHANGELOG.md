# 3.5.5-alpha.25 — Isolate live surface submission stalls

- Follow alpha.24 evidence of 105–281 ms buffer-post stalls with a controlled Live Screen experiment. Main records the existing shader drawing commands; a per-surface worker locks the hardware canvas, draws the immutable recording, and posts the buffer. CPU shader preparation remains on main.
- Allow only one submission in flight. Further capture/angle updates mark the view dirty, and the next frame uses the newest state. No backlog of captured frames is queued.
- Keep readiness transactions attached before submission, with existing main-executor commit listeners and generation validation. Completion of posting itself is not treated as readiness or visible pixels.
- Stop and join the worker before surface destruction returns. Worker code never waits for main; stale completion callbacks cannot restart a destroyed or replaced surface session.
- Add Live worker canvas timing for recording, queue/lock, draw, buffer post, and main completion. Preserve the capture delivery watchdog.
- Preserve shader geometry, buffer resolution and AA settings, smoothing/fade settings, handoff thresholds, screenshot rendering, and dual mode.

Validation: shader geometry checks plus release unit tests, lint, and APK build. Requires device validation of cover Home, repeated open/close reversals, rotation, screen off/on and switching modes. Expect slow posts may remain, but capture and angle delivery should no longer wait for those posts. Compare cover first-commit latency and new worker/main-completion timings; this is not a claim of faster native panel activation.
