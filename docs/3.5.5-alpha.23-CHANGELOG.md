# 3.5.5-alpha.23 — Live first-frame capture scheduling

- Give in-flight live capture completion sole ownership of scheduling its successor. Refresh ticks arriving while a capture is pending no longer poll every 16 ms, and completion coalesces queued refresh ticks before scheduling the next capture.
- Skip blur-pyramid preparation for live captures already invalidated by a newer generation. Keep the final generation, client, suspension and target-display checks before publishing a frame.
- Add bounded capture-stage timing during fresh-frame recovery: worker queue, capture IPC, blur preparation and main delivery. Add rate-limited slow canvas timing for buffer acquisition, painting and readiness/posting.
- Preserve screenshot scheduling, readiness gates, user fade settings, handoff angles, prewarming and alpha.22 angle polling.

This targets app-side work after remapping; native activation speedup and visible blackout reduction require device testing. Alpha.20 / CI187 remains the user-designated very stable rollback checkpoint (issue #24).
