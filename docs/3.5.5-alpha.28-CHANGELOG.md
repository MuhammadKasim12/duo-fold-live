# 3.5.5-alpha.28 — physical handoff startup diagnostics

Based on alpha.27 (alpha.20 runtime). Diagnostic build, not a stable promotion.

Adds a bounded, synchronized history of 12 physical-primary episodes, each limited to 32 events and 2500 ms. Both directions are recorded by physical identity; initial attachment is labelled. Display mode/state is recorded separately from host real-size geometry, exposing stale geometry without changing renderer decisions. Legacy cover trace is explicitly labelled unreliable for classification.

Records display callback observation, main-queue delivery, host remap and alpha/hide decisions, matching physical capture reception, first clear/fallback/glass draw, canvas lock/draw/post durations and a frame-attached transaction commit. A diagnostic transaction listener adds measurement overhead but never controls reveal or readiness. Invalidated callbacks are labelled. Missing measurements are not zero latency. No extra polling, screenshots or dumpsys are added. ON/commit are software evidence, not visible pixels.

Purpose: locate the ordinary-cover-before-glass gap. Timing starts at observed primary identity change, not physical photons or the device-state request; the existing request/power trace supplies those separate timestamps. Cover prewarm before primary remap remains in the existing power trace.

Rendering, power, angle thresholds and smoothing are unchanged. The alpha.26 wallpaper changes are not included in this baseline experiment. Alpha.20 remains the stable rollback checkpoint.

Test: five complete open/close cycles on Home, then five inside one fullscreen app; pause about three seconds at endpoints. Export a separate report for each context. Note whether the cover briefly shows unblurred content and whether any screen stays dark. A short external video helps correlate the software trace with visible output. Do not promote until the cover flash is fixed and verified on-device.
