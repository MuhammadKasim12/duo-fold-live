# Duo Fold Live 3.5.5-alpha.10

Incoming overlay opacity fix candidate, based on the alpha.9 device test.

The user observed a clean raw capture but app text showing through solid magenta. That places the observed duplication after capture, even when the glass shader is bypassed.

- Replace the secondary application-overlay Dialog with a service-owned accessibility-overlay window, using the existing NativeInnerOverlay attachment pattern. Android's application-overlay policy can cap non-touchable window opacity; the working Live Screen window already uses the accessibility-overlay type.
- Request window alpha 1.0 with no window animation, retaining non-focusable/non-touchable behavior. No system opacity setting or private trusted-overlay flag is changed. No fallback to the previous semi-transparent application-overlay type.
- Preserve physical-panel ownership, pre-attachment, captured frames, capture exclusions, shaders and outgoing primary screenshot rendering. Task routing, full-close release, power handling and default-on wallpaper wake preparation are unchanged.
- Retain Normal animation / Raw capture / Solid magenta developer tests. The screenshot report adds the secondary window type and requested/view alpha, plus bounded system window attribute/alpha fields in snapshots. Requested values do not prove effective pixel opacity.

## Test

1. In Screenshot Mode select Developer settings → Incoming ghosting diagnostic → Solid magenta. Fold and unfold slowly; pause midway for at least three seconds. App text should no longer show through magenta on the incoming panel.
2. Select Normal animation and repeat. Check for duplicated text inside the animated region.
3. Copy the screenshot-mode test report if either test fails, or if the destination window does not attach. Endpoint blanking remains a separate deferred issue.

Reference: AOSP DisplayPolicy change a451d5bae2e2fb1e75152c596a6f476d6f7ac1ec (cap non-touchable system-alert-window alpha). The exact Samsung compositor behavior still requires this device test.
