# Duo Fold Live 3.5.5-alpha.6

Screenshot-mode live incoming animation test.

- Keeps the outgoing screenshot frozen. After the exact fullscreen app is verified on D1, refreshes its animation from live overlay-excluded D1 captures. Previously this animation reused a single screenshot.
- Checks physical identity, display, destination size, capture age and post-verification timestamp before accepting live frames. Clears stale incoming content; invalid sessions release their capture client.
- Incoming startup retries remain available throughout the bounded concurrent session, instead of silently stopping 2.5 seconds after concurrency began.
- Adds “Copy screenshot mode test report” in Developer settings. Throttles incoming draw logging to once a second.
- Home/Recents routing remains unsupported in this path. Native endpoint remapping may still blank; this build does not claim to fix it. Normal live mode and default-on wallpaper wake preparation are preserved.

## Test

1. Select Screenshot Mode (hold its card for 10 seconds if still locked). Its window-first option is set automatically.
2. Start closed, open a fullscreen app with changing content, then unfold slowly. Pause around 100–140 degrees for 3 seconds, below the fully-open threshold.
3. Check that the cover image remains frozen while the inner content changes and the animation responds to angle. Then finish unfolding.
4. Close slowly once. Copy the screenshot-mode test report and note whether any problem happened at startup, during the pause, or at the final switch.
