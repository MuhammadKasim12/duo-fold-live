# 3.5.8-alpha.12 — Samsung notification background experiment

- Replace both existing system-compositor experiment implementations with Samsung SemBlurInfo window blur in an owned windowless child above the renderer. Preserve experiment IDs and the default normal glass renderer.
- Use the measured notification-background recipe: target radius 250 screen pixels at standard strength, identity color curve, BG adjustment 0.10 with bounds 0.18 and 0.75. No notification-card or Recents color curve. Separate notification_blur_radius preference avoids inheriting the prior 120 buffer-pixel setting. Radius range 0–500 screen pixels before strength scaling.
- Retain the moving cover/right and inner/left mask and 64-strip feather. This release does not claim a continuous Samsung gradient: its semantics have not been verified. All strips share a radius and use blur-drawable alpha. Owned layer is excluded through its capture-excluded parent, non-touchable/non-focusable, and hidden before release.
- Vendor payload construction goes through View.semSetBlurInfo rather than guessing SemBlurRegionData/native layout. API rejection or missing drawable hides/releases the child and reports projection without blur. Host attachment may require an initial frame. Blur host rendering is asynchronous; parent visibility/crop is submitted with the projection, but no atomic pixel alignment is claimed.
- Move Auto-rotate recovery below Folding Mode and above Trouble with Shizuku. Existing journal recovery and default glass behavior unchanged.

Evidence: notification shade and Recents Fold Observer dumps dated 2026-10-22, summarized in NOTIFICATION-BLUR-FINDINGS.md. On-device API inventory confirms SemBlurInfo builder methods; view-host and vendor behavior need handset validation. Older Samsung View source was consulted for the background-drawable pathway, not treated as the exact test firmware. No performance or optical-quality claim.

Validation: CI must run unit tests, lint, release build, and signature/alignment checks. Device checks: select notification background + stretch, fold both directions and reverse, verify clean inner half and zero effect at endpoints, then compare normal glass and check relocated recovery control. Report Samsung API status on failure.
