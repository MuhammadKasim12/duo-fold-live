# 3.5.5-alpha.21 — Reduce live handoff UI-thread work

- Retain the 1px logical-display angle anchors across live panel remaps; eliminate remove/add window IPC caused solely by changed panel dimensions.
- Snapshot anchor tokens on main and send live wallpaper angle commands on the existing IPC worker before reading the reply. No View operations move off main. Polling remains single-flight with the same command/read ordering.
- Resolve transitional old-panel bounds against the current rotated display mode in the live host and live renderer capture validation. Preserve matching scaled logical bounds. Screenshot geometry handling is unchanged.
- Add rate-limited timing for main setup, worker queue, wallpaper commands, reader IPC and reply delivery to identify remaining stalls rather than attributing every delay to native power activation.
- Keep alpha.20's bounded closing prewarm and prepared renderer retention. No changes to artificial fade settings, reveal duration, readiness policy, or handoff thresholds.

Validation: unit cases cover opening/closing geometry, rotation, resolution scaling and invalid mode fallback; shader checks and Android CI run before delivery. On-device timings and wallpaper-command behavior with retained anchors still need confirmation. This changes app-side handoff work, not Samsung's native remapping implementation.
