# Duo Fold Live 3.5.5-alpha.4

Updates the existing **Prepare custom wallpaper before unlock (test)** developer toggle. Test-off behavior remains unchanged.

- The Home handoff requires a photo transaction committed during the current wake episode and a recent sample identifying Home as active. An attachment callback alone is no longer sufficient.
- After the original one-second hold, missing Home readiness triggers refresh/reattachment retries for at most two additional seconds. Failure is explicitly reported and cleaned up; another foreground app, screen-off, disable and host shutdown retain cleanup behavior.
- A ready Home photo is shown and the bridge hidden in one transaction; normal bridge resource cleanup waits for that transaction's commit callback, with bounded timeout cleanup.
- Reports include current wake episode, Home/SystemUI target availability, preparation eligibility, Home commits, handoff commits, and sampled wallpaper/SystemUI/launcher window visibility. Snapshots are bounded metadata and can include window/app names, but contain no screenshots or audio. Software commit/visibility samples do not prove optical continuity.
- Prior successful glass shading and cover-close handling are preserved. Includes 40% default/reset glass strength.

After any flash, copy the wallpaper wake test report immediately. Also say whether the flash occurred immediately upon unlock or roughly one second afterward. An external camera is not required.
