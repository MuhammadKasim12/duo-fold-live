# 3.5.3-alpha.34 — Capture recovery after wake

- Existing 250 ms monitor retries capture resume after the primary screen is ON and keyguard is unlocked, even if SCREEN_ON preceded unlock or USER_PRESENT was missed.
- Resume is idempotent: one fresh-frame request and a bounded 1.5-second capture warm-up, with fast retries while the helper reconnects. Regular renderer clients remain independent.
- Logs suspension, resume, missing exclusion surfaces, capture failures, and first successful post-wake capture.
- No animation geometry, tuning, handoff, or wallpaper implementation changes.

Device test: sleep unfolded, unlock, fold immediately; repeat with a delayed first fold and from folded wake. Inspect Glass wake recovery lines if black fallback persists. This repairs a demonstrated recovery gap; device results are not yet verified.
