# 3.5.5-alpha.12 — bounded ON hold at primary remap

Alpha.11 device result: the visible flash moved to the primary remap. Both displays reported OFF there; subsequent endpoints for promoted sessions did not show another incoming OFF sample. System controls followed D0. This did not fix the overall interruption.

- Enable the remap ON-hold experiment by default using a new screenshot-only preference; its Developer toggle provides an OFF comparison. Existing normal live mode is unchanged.
- Request Samsung ON overrides for D0 and D1 immediately before replacing the concurrent-state request. Wait asynchronously for the API result, bounded at 500 ms; rejection or timeout proceeds with the existing route and is explicitly logged.
- Release both owned overrides after two seconds; also clear on stop, disable, stale input, unrelated loss of usability, reversal or handoff error. Cleanup retries are generation-bound so an old retry cannot clear a newer session.
- Preserve alpha.11 handoff angles and alpha.10 accessibility-overlay ghosting fix. Retain power, physical-identity, app-readiness and navigation/taskbar snapshots, adding ON-request phases.
- The vendor call shape and trailing value are inherited from the documented alpha.13 experiment; their precise Samsung Android 17 semantics remain unverified. An accepted API call is not evidence of effective display power or optical continuity. No wake/sleep call is added.

Validation: CI compilation, unit tests, lint, shader checks and APK signature verification. Device test: one slow unfold and fold with Normal animation and the new hold toggle ON; report any midpoint flash, endpoint flash or delayed flash around lease expiry. Copy the screenshot-mode report. Compare OFF if needed. This is an experiment, not a confirmed blackout fix.
