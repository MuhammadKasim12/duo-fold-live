# 3.5.5-alpha.17

- Reverts alpha.16 screenshot timing changes exactly: restores fade-setting-derived reveal duration, duplicate readiness verification/settle, shared readiness queue and prior release sequencing. Wallpaper gesture improvements remain.
- Live Screen only: skips the redundant device-state query when replacing Duo’s own active request. The check for another override remains when initially acquiring control. Android still arbitrates requests.
- Adds decision-to-submission, Binder return and request-active callback timing to normal handoff traces. Request-active is not proof of physical panel activation.
- Live fade settings, readiness checks, switching angle, preview commit gate and Android-managed closing fallback are unchanged.

## Investigation

The Live Screen path is AngleReader → PreviewExpansion holdBeforeRelease → CoverHandoff → DeviceStateManager.requestState. The preview commit gate can delay submission by up to 80 ms, plus heartbeat scheduling. It protects the prepared frame and is not removed without device evidence. HandoffFadePolicy controls artificial masking separately and does not activate displays. The closing 1000 ms timer is a fallback awaiting Android cancellation, not a mandatory one-second delay. Samsung activation/remapping latency requires device measurement; this build does not claim a measured improvement.
