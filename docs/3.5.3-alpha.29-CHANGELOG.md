# 3.5.3-alpha.29

Disable both extra endpoint cover-up experiments at the owner's request:

- IncomingHold's black endpoint mask and reveal fade are disabled internally.
- IncomingHold's extra screenshot covering Home/wallpaper at the final display transfer is disabled internally.
- Remove both controls from Developer settings. Screenshot Mode selection no longer enables the fade. Clear legacy preferences on startup, with an unconditional internal execution gate so saved settings cannot reactivate either feature.
- Diagnostics explicitly report both features as disabled.

The ordinary selected folding animation, outgoing screenshot, and clean incoming animation input remain. IncomingAnimationFrame is the animation's input during motion, not the parked endpoint screenshot cover-up. Live Screen remains the default. The underlying Samsung display switch may still black out or briefly expose Home/wallpaper; this build deliberately stops trying to mask it with these experiments.

## Retained implementation for future investigation

IncomingHold.kt retains preattached HoldWindow hosts, optional exact-app screenshot capture, EndpointFadePolicy masking, IncomingHoldLease timing and readiness-based reveal. Its endpointExperimentsEnabled gate is false. Re-enabling requires an intentional source change; there is no app toggle. EndpointFadePolicy.java, IncomingHoldPolicy.java, IncomingHoldLease.java and their tests are retained. Do not re-enable automatically through mode presets.
