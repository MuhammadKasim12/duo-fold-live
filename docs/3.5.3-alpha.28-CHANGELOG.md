# 3.5.3-alpha.28

Address remaining incoming-screen ghosting by removing the attached SurfaceView from the incoming Screenshot Mode renderer. A regular hardware-accelerated View now records the same opaque shader projection directly into the overlay window buffer, with a bounded saveLayer for transparent regions. The shader painter is shared without attaching its SurfaceView or allocating a child surface. This avoids an independently composed animation layer and SurfaceView hole over the live app.

Retain the pre-animation exact-app capture, selected style, inner live right half, endpoint black fade, and Live Screen default. Live Screen and outgoing screenshot rendering use their existing surface path. Log the first incoming window-buffer draw per capture for verification. Device confirmation is required; this is a composition fix candidate, not an optical pass claim.
