# Duo Fold Live 3.5.5-alpha.33 — reduce repeated runtime work

Performance pre-release based on user-validated alpha.32. Stable release remains unchanged.

- Build and transfer optional helper diagnostic histories at most every 500 ms. Every poll still carries live angles, freshness, readiness, routing and safety controls. The app retains omitted diagnostic snapshots; timestamps remain event timestamps.
- Cache read-only runtime preferences in an application-scoped snapshot refreshed by preference-change notifications. Reconfigure preview settings only after a settings revision.
- Merge poll-driven secondary refresh requests at the next display frame. Display/lifecycle refreshes still run immediately and cancel redundant pending callbacks. Rendering remains on its existing thread.
- Coalesce fresh-capture invalidations before the next capture starts. An in-flight resize still invalidates its capture. Check generation before and during the seven-level mip build; discard unpublished stale buffers and retain the final generation/display validation.
- Keep only one scheduled capture tick after a worker completion. Format capture-rate status at most once a second (or on destination changes/recovery), without throttling frame publication.
- Add on-demand capture processing diagnostics: last mip-build time, main delivery queue time, obsolete captures discarded and merged fresh requests. These are software timings, not optical measurements.

Unchanged: black wait/reveal policy, confirmed removal and retries, handoff thresholds, smoothing, visual quality, capture target and renderer thread. APK shrinking/minification remain disabled.

Validation: diagnostic cadence tests plus existing unit tests, curve/shader checks, lint, release build/signing. Device validation still required: repeat alpha.32's folds, slow/fast reversals, portrait/landscape and settings updates. Compare main display queue and physical remap-to-fresh GLASS_COMMIT timings; do not infer sustained FPS from one status sample. Preserve alpha.32 as rollback.
