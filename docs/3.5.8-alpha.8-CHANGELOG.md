# 3.5.8-alpha.8

Normal presentation restored after alpha.7 diagnostic bypass.

- Prepared renderer selection follows cached physical-panel identity on display callbacks, without waiting for Compose to update the host. Captures are also delivered directly to the selected renderer.
- Primary identity/rotation changes invalidate the capture source once. Output resize wakes capture without discarding in-flight source work; duplicate output callbacks preserve readiness. New active surfaces still invalidate capture to refresh exclusions. Screenshot-mode source behavior retained.
- Added capture/processing/delivery timing to startup diagnostics.
- Developer settings: Normal glass (default), Lightweight glass (quarter-resolution output, one mip-filtered sample instead of 25 blur taps), Projection only, System compositor blur.
- System compositor experiment requests SurfaceControl background blur on the owned renderer surface, rendering transparent pixels instead of projected glass. This tests the mechanism observed in Recents, not Samsung's complete effect. Capture remains for readiness; API rejection falls back to projection-only. Android can suppress blur even when a transaction succeeds. Blur clears on inactivity, standby, or surface destruction. Separate SYSTEM_BLUR draw/commit labels avoid treating it as projected glass.
- No claim of measured device latency improvement until on-device testing. Compare normal first, then modes using the same app and fold speed.
